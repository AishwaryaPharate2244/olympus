Every value a config holds should be able to say where it came from, and that answer needs to survive everything the config is put through.

A value loaded from a YAML file reports the file and the line and column where its own text begins, counted from 1: a scalar's own start, a block mapping's first key, a flow collection's opening bracket, a quoted string's opening quote. An alias, or a value pulled in through a merge key, reports the anchored text's position, not the reference site. Built straight from YAML text rather than a file, the same kind of record carries no file. A value built directly from Python, or left at its dataclass or attrs default, is distinguishable from one actually supplied: an explicit value equal to the default still counts as default, recursively into nested dataclass fields. Entries from a dotlist or the command line report the exact entry text that set them, including any structure only that entry had to create; a later entry adding a key under an already-created container leaves that container's record alone.

Merging follows the shape of what happens. Something replaced, or filled in from missing, null, or an unresolved reference, takes the supplying side's record. A nested mapping merged key by key keeps its own record while its keys update underneath it; a key the merge adds takes the source's record. A list, whatever its type, is never merged element by element: replacing it takes the source list's record, and every element takes its matching source element's record rather than a fresh default. A plain dict or list used as a merge source counts as Python. Assigning directly, or appending or inserting into a list, always marks the result Python, replacing whatever was there.

Copying, deep copying, pickling, a masked copy, and resolving an interpolation never change any of this. An interpolation reports where its own expression was written, never where it resolves. Wherever a value sits behind a type holding more than one alternative, whichever is selected participates the same as anything else, never skipped as an opaque wrapper.

The five words for where something came from are file, yaml, python, dotlist, and default. Give the library a small record type, something like Provenance, with a kind field holding one of those words plus optional source, line, and column fields, readable from outside. Add a method on the main entry point, something like get_provenance, taking a config and a key path in select's own notation, returning the node's record or a clear empty answer if the path does not resolve. Add a companion, iter_provenance, walking every value reachable from a point, yielding each path with its record. Add a third, provenance_diff, taking two configs and reporting every path where their records differ, including a path only one has. Add a fourth, to_annotated_container, converting a whole config to a plain nested structure whose own record and value or children come back together at every level, not only the leaves.
